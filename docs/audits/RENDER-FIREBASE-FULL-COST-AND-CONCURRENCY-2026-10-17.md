# Capacity and whole-platform cost audit, 17 October 2026
**Scope:** release/current American Rider Commercial source, Render-connected service, public provider pricing. **Audit only.** No paid upgrade or production deployment. This is not the capacity of a tested $7 or $25 instance.

## Correct previous claims
- **Withdraw** the former estimates of 25–50 simultaneous Travels on $7 and 50–150 on $25. Neither figure was measured or has a supported basis. A "simultaneous Travel" is a persisted workflow with intermittent I/O, not a dedicated occupied Render worker.
- **Server vs workspace:** Starter is 0.5 CPU / 512 MB / $7 per instance-month; Standard is 1 CPU / 2 GB / $25 per instance-month. **Neither** includes automatic scaling. Autoscaling requires the separate **$25/month Pro workspace**, configuration of min/max instances and CPU/memory targets. Multiple instances cost separately; Hobby workspaces can manually scale paid services. Render source: https://render.com/pricing , https://render.com/docs/scaling .
- Connected Render service `American-Rider-Server` is `0.5c-512mb`, **one** Ohio instance on `release/current`; latest known live deploy is `e3f0ba4`, newer deploy attempts hit build pipeline limits. Idle ~131 MB RAM, CPU tiny, essentially no revenue traffic. This **cannot establish throughput**. Render build minutes and workspace bandwidth are separate from instance compute.

## Actual code paths and financial model correction
- `src/backend/telemetry.ts`: a moving, onboard Travel may write `rides.opLat/opLng/opAt/stillSince` **once per 15 seconds** (240 writes per full hour, 120 for 30 minutes). The old forecast of 40 writes per Travel **cannot represent all activity of such a Travel**. No per-ride price model should silently exclude this.
- `src/state/OperatorContext.tsx`: foreground Operator duty refresh nominally every **90 seconds**. `backend/server.js` `/operator/online` performs repeated eligibility, Firebase and sometimes Stripe work and updates the Operator record. Assumption of **seven reads and one write per renewal is illustrative**, not measured. Background GPS cadence differs with device state.
- `backend/monitor.js`: minute-by-minute query returns all active `accepted/arrived/onboard` Travels, paged. ~60 active document returns/hour per continuously active Travel, excluding empty-query billing, retries and other monitoring work.
- `backend/geooperators.js`: two levels of up to nine geohash cells and up to 120 results per prefix; at saturation, current code re-fetches a 120-result page after a 40-result page (the 40 overlap). Worst-case requested docs in 18 saturated cell queries can approach 18*(40+120)=**2,880** document returns per dispatch, before cross-tier overlap, index billing or retries. **Not** an average. Draft PR #62 addresses pagination/nearby-first, while separate draft PR #81 improves processing/concurrent verification; neither is live.
- `backend/server.js` `/operator/settle-pending` currently searches all `rides` for one Operator with no limit, then filters unpaid/completed results in application code. This is a **remaining read-amplification risk** and needs a safe, migration-aware indexed payout-worklist design. Do not silently drop legacy obligations.
- Existing `backend/fleet-economics-forecast.js` uses 100 reads/40 writes per Travel **plus** its separate presence budget. These are illustrative financial inputs, not actual per-Travel Firestore read/write counts.

## Illustrative *sustained* one-hour operation scenario: SAME database work on $7 and $25
Assume each active Travel lasts 30 minutes, with as many additional **idle** on-duty Operators as active ones; each on-duty Operator renews 40 times/hour with **7 reads + 1 write each**; each active Travel publishes 240 positions/hour with **2 live observers** each receiving 240 updates; each active Travel is monitored 60 times/hour; each completed Travel has **a further 100 reads and 40 writes** for other lifecycle activity. These are independent assumed categories, **not measurements**. The per-Travel 100/40 excludes the counted GPS/duty/monitor/listener activity. Actual device state, index entries, dispatch density and external APIs can change everything.

## Other price and capacity dependencies
- **Stripe:** current published US domestic card fee 2.9% + $0.30 on successful charges ($0.88 per $20 Travel); extra for international cards/conversion; Connect platform-controlled payout pricing is $2/month per active paid-out account plus **0.25% + $0.25 per bank payout**. App's economic policy also models a 0.25% funds-routing component: verify account contract, Stripe balance transactions and schedule before calling this a real fee. Refunds, disputes, failure retries, unused payment intents and reserve also matter. https://stripe.com/pricing , https://stripe.com/connect/pricing
- **Maps and routing:** the actual mobile vector map uses MapLibre + public OpenFreeMap tiles; its $0 tile price has no contractual availability guarantee. `backend/place-search.js` uses **HERE Autosuggest**, cache ten minutes per server; `backend/tolls.js` uses HERE routing/tolls with one-minute verified cache; `backend/streets.js` calls a configured self-hosted OSRM or OTP. HERE request rates, production license and RPS limits **unverified**. HERE's Base/Limited plan excludes certain Asset Management use, potentially material to transportation dispatch; seek direct written license confirmation before reliance. Routing/OTP hosting and transit feed providers can incur independent costs.
- **Messaging & delivery:** Firebase Cloud Messaging itself has no charge; Expo native delivery and iOS/Android receipt require commissioning. Resend Free/Pro ($20 for 50k/month plus overage) and transactional email volume; SMS if phone verification or support messaging is used; remote support, fraud and customer-care staffing.
- **Hosting:** Render $7/$25 per instance; Pro workspace add $25; build minutes and bandwidth allowances/overages; two Commercial static sites use shared included bandwidth and build minutes; no extra CPU charge for free static sites. Paid OSRM/OTP route engines would be additional services when enabled.
- **Firebase Blaze:** paid usage for Firestore, Cloud Storage document/insurance uploads/downloads, network egress, authentication (phone verification), backups/TTL/backup and optional advanced features. Blaze is not a flat monthly subscription.
- **Legal/company obligations:** independent insurance screening/verification suppliers, corporate legal/regulatory obligations, chargebacks, airport/port permits, accounting, security, monitoring, audit/retention and staffing are not included in the example table.
