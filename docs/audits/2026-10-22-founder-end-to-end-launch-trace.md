# American Rider | One systematic end-to-end launch audit
22 October 2026 | Scope: **source and deterministic synthetic paths**, commercial `release/current` baseline `dc96dd77`. Not signed-device or live-provider certification.

## Executive disposition
The platform already has substantial server-side safety and recovery machinery. Do not rebuild it or require a public user to run synthetic tests. Preserve the existing single paid **Google Cloud Run** production API and its one authenticated Scheduler, Stripe live webhooks, Firestore, bounded geohash dispatch, existing Ops/Resend support, and Founder-only controls. Never use a Render preview/source deployment as proof of Cloud Run runtime readiness.

Two concrete cross-layer discrepancies were found and corrected in this PR:
1. **Operator money display:** `app/operator/complete.tsx` subtracted the full Operator estimate (99% Fare **plus toll reimbursement**) from Fare to claim the Platform commission. A $17.80 Fare with $2.75 toll reimbursement pays the Operator $20.38: the old display would compute a **negative $2.58 commission**, when the correct commission is **$0.17**, plus $2.75 reimbursed tolls. It also said an estimated amount had been **added to revenue** without an independently confirmed Stripe transfer. Now the amount is explicitly an estimate; the commission and reimbursement are separate, exact-cent rows; stale records with missing toll evidence do not fabricate a breakdown. The 99% Fare policy, server charges, transfers, payouts and traveler Total are unchanged.
2. **Cost / Operator inbox:** `src/backend/operatorInbox.ts` subscribed to every historical Travel sharing `operatorId`, including terminal records. The listener now includes only `assigned`, `accepted`, `arrived` and `onboard`. The existing declared Firestore composite index `rides(operatorId,status)` supports that filter. It uses no arbitrary record cap (which could hide a still-live journey), new index, new database read, new poller or service. A read failure remains visible.

### Open engineering or real-world evidence boundaries
- **P1: accepted Operator emergency withdrawal**. `OperatorContext.cancelOp` deliberately goes off duty without pretending it released an **accepted** Travel. `travelprogress.js` only permits normal decline from `assigned`, not `accepted`. The accepted-withdrawal to safe reassignment/refund pathway is **not fully supported** here. Design a narrow, authenticated server exception path with Traveler notification, actual payment/hold reconciliation, and safety-first behavior before advertising an Operator cancellation control. Do not shortcut by clearing local state or accepting a forged 'declined' phone write. Existing emergency/Support escalation should remain accessible.
- **Runtime commissioning not proven by source**: Google Cloud Run latest serving SHA and declared `rides(operatorId,status)` index readiness were not independently read from production Google credentials in this review. The code and index manifest are confirmed, not live index status. Do not claim new production deployment from a merge.
- **External acceptance**: real signed iOS/Android device wallet/3DS behavior, real qualified Operator/CRA/insurer evidence, verified Connect bank transfer and store review are not synthetic outcomes. Public app users are not required to run the offline suites. No new TestFlight/EAS build authorized.
- **Legal boundary**: Florida Statute §627.748(7)(d) needs qualified Florida TNC coverage/defense assessment. Reviewing statutes and published guidance is not equivalent to having retained legal counsel.

## Controls and cost
One deterministic runner `scripts/prelaunch-synthetic-acceptance.cjs` now executes **20 existing/new** suites in isolated subprocesses with no provider credentials. It runs in the existing PR Release Gate and before already manual-authorized signed builds. This does not spend money on extra cloud vendors, introduce H3, alter duty heartbeat/GPS, charge a card, request new indexes, create traffic or contact users. Treat UI compensation as estimates until Stripe confirms transfer; keep server ledger distinct from mobile local numbers.

## Institutional foundations
- Google SRE, [Eliminating Toil](https://sre.google/workbook/eliminating-toil/): reduce predictable founder interrupts and avoid adding operational dependencies.
- Google, [Firestore best practices](https://firebase.google.com/docs/firestore/best-practices) and [transaction contention](https://firebase.google.com/docs/firestore/transaction-data-contention): bounded queries, indexed lookups, safe retry semantics.
- Apple, [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles) and [feedback](https://developer.apple.com/design/human-interface-guidelines/feedback): actual outcome before claiming success and clear recoverable statuses.
- Stripe, [Idempotent requests](https://docs.stripe.com/api/idempotent_requests): the same action retried must not create a second charge.
- Florida Legislature, [§627.748](https://www.leg.state.fl.us/statutes/index.cfm?App_mode=Display_Statute&URL=0600-0699/0627/Sections/0627.748.html).

**Boundary:** This is a source-and-synthetic audit, not a claim that an independent lawyer, insurer, Apple, Google or a bank approved American Rider. Keep source merged, Cloud Run deployed, app signed, stores approved and real paid operations as separate statuses.
