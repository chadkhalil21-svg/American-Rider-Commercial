## Confirmed source gaps requiring a decision/fix
1. **Sign in with Apple token revocation on account deletion** [Issue #358](https://github.com/chadkhalil21-svg/American-Rider-Commercial/issues/358). `src/state/appleSignIn.ts` reauthenticates via Apple and `app/delete-account.tsx` submits to `AuthContext.deleteAccount`, which calls Firebase deletion. No Apple authorization-token revocation is implemented in these paths. The existing `docs/COMMERCIAL-RELEASE-EVIDENCE.md` already calls for this requirement, yet code tests don't enforce it. Apple's guidance requires provider-token revocation when available, or manual-revocation guidance when tokens are unavailable. Password account success does not prove Apple-account compliance. **Cannot mark Apple provider deletion complete.**
2. **Hand-drawn Apple sign-in logo** [Issue #359](https://github.com/chadkhalil21-svg/American-Rider-Commercial/issues/359). `src/screens/AuthScreen.tsx` contains a manually authored SVG Apple silhouette and itself notes Apple-approved artwork remains outstanding. `backend/auth-sso-visual-parity.test.js` checks spacing and custom glyph geometry but not the artwork provenance. Apple HIG permits custom buttons but requires Apple-provided logo artwork. Preserve the two founder-approved Continue with Apple/Google buttons when correcting. **Native-code review risk; a replacement in signed app requires another binary.**

## Separate evidence gaps, not proven defects
3. **Signed Build 56 differs from newest native source.** [PR #355](https://github.com/chadkhalil21-svg/American-Rider-Commercial/pull/355) added the `americanrider` iOS URL scheme for deep links *after* Build 56 was submitted. Its CI checks current source, not Apple's installed Build 56. This is material to Family/Teen/referral deep links; no proof those entry points work in Build 56. If that native fix is required for the public binary, upload a new signed build rather than assume current GitHub fixes retroactively affect Build 56.
4. **Cloud Run exact-release parity not established.** Authenticated [read-only workflow 40433663228](https://github.com/chadkhalil21-svg/American-Rider-Commercial/actions/runs/40433663228) on 2026-10-27 UTC reports production `/live` HTTP 200, verified runtime identity, Stripe secret mounted, current Cloud Run revision `american-rider-api-production-00032-nn4` ready; the explicit store-source check prints `BLOCKED: Production Cloud Run revision does not match the certified release SHA`. The current branch includes mobile-only, test, ledger and IAM scripts after the last API source deployment; mismatch does not itself establish a runtime bug. Reconcile only source changes that affect the API; do not deploy financial code merely to equalize a documentation-only SHA.
5. **Apple review-access proof missing.** The October 26 Apple Guideline 2.1 Information Needed message asks for a physical-device screen recording showing typical launch/registration/login/deletion, applicable UGC reporting/blocking or paid-feature access, plus purpose/audience, review credentials and setup, external services, regional behavior and relevant regulated-industry documentation. Apple general policy requires a valid demo account or fully-featured demo mode for account-based features, additional roles included. One video of accessible Operator qualification screens is not proof that Apple's reviewer can inspect commissioned screens. Do not qualify a real Operator via fabricated policy or screening; provide appropriately isolated and accurate review access, and explain prelaunch no Operator availability.
6. **Provider and wallet device coverage.** The successful deletion report does not verify Apple/Google social sign-in deletion or that Stripe setup can save a card. `app/wallet.tsx` has real provider calls and loading/error handling, but real supported-device results and API provider records were not supplied. Classify as **unverified**, not failed.
7. **App Store Connect rejected state.** User screenshot shows iOS 1.0 Build 56 `Rejected` under 2.1 App Completeness, requesting additional information because of limited review history. No connected App Store Connect action is available here to submit the reply. Apple's official sequence is Reply to App Review, Edit rejected app item, Add for Review, and Resubmit to App Review. Same build may be resubmitted if review-information-only; any native fix needed for the released app requires a new signed build.

## Conservative conclusion and execution order
1. Retain verified Firebase password-style deletion fix. Record real provider used only if independently known; do not infer from a screenshot.
2. Resolve Apple provider-token revocation and Apple-logo compliance *before* asserting every account type is App Store-ready; keep them as independently testable, narrow issues.
3. Determine whether Build 56 lacks a mandatory native deep-link path, and whether changing either Apple issue requires a replacement signed binary. Existing App Store submission is not changed by code merged after upload.
4. Prepare Apple's actual six written answers and a genuinely valid review-credentials/multi-role setup. Prelaunch no-Operator and no-completed-Travel are explained, not fabricated.
5. Read exact deployed Cloud Run source/paid-provider evidence through the existing privileged read-only audit. If a *material backend difference* exists, use the current approved controlled deployment; do not run an unrelated broad activation.
6. Never call release complete solely because CI is green; maintain explicit per-feature `source / deployed / provider / signed-device / Apple accepted` evidence.
